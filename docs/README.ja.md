# unnotator

**拡張機能であらゆる形式に対応できる、汎用のアノテーションツール。**

[English](../README.md) · [ライセンス: MIT](../LICENSE)

unnotator は Tauri v2（Rust）と SolidJS/TypeScript で作るデスクトップアプリです。アカウントもサーバーも要らず、すべて手元のマシンだけで動きます。

コアは媒体を知りません。画像・テキスト・音声などの扱いは、別リポジトリの拡張機能が担います。コアが管理するのは、プロジェクト、アノテーション、関係、ラベル、Undo/Redo だけです。

> **状況: 開発の初期段階です。** 今あるのはリポジトリの土台（ワークスペース、ビルド、型付き IPC、契約の検査）だけで、アプリは空のウィンドウを開きます。注釈を付けられる機能はまだ無く、リリースもありません。

## 設計の方針

- **媒体を知らないコア。** 座標・ピクセル・時刻・文字位置はコアに入れません。基準は「音声ファイルでも意味があるか」です。
- **媒体の処理は拡張機能。** 拡張機能はマニフェスト（`unnotator-plugin.json`、JSON Schema で検証）で記述し、型付きの `@unnotator/plugin-api` に沿って書きます。
- **書き込みの入口は 1 つ。** プロジェクトのデータは Rust のコマンド層だけが変更します。JavaScript でも Python でも、拡張機能がデータベースを直接触ることはありません。
- **完全ローカル。** 外部への通信はしません。CSP は厳しく設定し、`withGlobalTauri` は無効です。

## リポジトリの構成

| パス | 役割 |
| --- | --- |
| `crates/core` | プロジェクトのデータと DB スキーマ（Rust ライブラリ。Tauri に依存しない） |
| `crates/extensions` | 拡張機能のマニフェストのスキーマ（Rust ライブラリ） |
| `crates/worker` | 拡張機能のプロセスとのプロトコル（Rust ライブラリ） |
| `src-tauri` | Tauri アプリ本体 |
| `src/` | SolidJS のシェル。Rust との通信は `src/ipc/` を経由する |
| `packages/plugin-api` | `@unnotator/plugin-api`: 拡張機能の作者向けの TypeScript の型定義 |
| `config/` | ツールの設定（Vite・Vitest・Biome・Clippy） |
| `scripts/` | リポジトリ用のスクリプト（検査・計測） |
| `docs/` | 文書（日本語の README を含む） |

依存の向きは一方向です。`src-tauri → crates/*`、`worker → extensions → core`。

## はじめかた

### 必要な道具

| 道具 | 版 |
| --- | --- |
| Rust | `rust-toolchain.toml` で固定（rustup が自動で入れる） |
| Node.js | 24 以上 |
| pnpm | 10 系（`corepack` で有効にする） |

Tauri のために、OS ごとの前提もあります。

- **macOS:** Xcode Command Line Tools（`xcode-select --install`）
- **Linux:** WebKitGTK など。Debian/Ubuntu なら `libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf libssl-dev`
- **Windows:** Microsoft C++ Build Tools（MSVC）と WebView2

### 入れて動かす

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm tauri dev
```

`corepack enable` が権限で失敗するときは、`corepack enable --install-directory <PATH 上の書き込める場所> pnpm` を使ってください。

## プロジェクトのフォルダ

プロジェクトはフォルダです。データはその中の `.unnotator/` に入るので、フォルダごと移動・コピー・圧縮しても、どこでもそのまま開けます。

- `.unnotator/project.db` がプロジェクトのデータベースです。`.unnotator/lock` は、同じプロジェクトを別のアプリ（や別のウィンドウ）が同時に開くのを防ぎます。アプリが異常終了しても OS がロックを解放するので、後始末は要りません。ロックが確実に働くのはローカルのディスクです。ネットワークドライブでは OS が保証しないことがあるので、プロジェクトはローカルのディスクに置いてください。
- アプリの更新でデータベースの形式が変わったときは、開くときに自動で移行し、移行前の内容を `.unnotator/project.db.bak` に残します。新しいアプリで作られたプロジェクトは、書き換えずに開くのを断ります。
- 開いている間の編集は、アプリのデータフォルダ（`recovery/`）にある作業用の複製と変更履歴に入り、`project.db` は保存したときにだけ変わります。保存は、隣に新しいファイルを書いてから入れ替えるので、保存の途中で落ちても電源が切れても、書きかけのプロジェクトが残りません。保存している間も編集を続けられます。
- 未保存の変更があるまま閉じるときは、保存するか破棄するかを選びます（閉じるのをやめることもできます）。アプリが異常終了したときは、次にそのプロジェクトを開くときに、変更の件数と最後の変更の時刻を示して、復元するか破棄するかを尋ねます。選ぶまでは何も消えず、復元すると Undo の履歴も（最大 500 件）作り直します。紐づくプロジェクトが無くなった作業用データは、30 日後に自動で削除されます。一覧から手で削除することもできます。

### アセットと設定

- **アセット。** プロジェクトのフォルダの下のファイルは、プロジェクトを開くと自動でアセットになり、開いている間に増えたファイルも取り込まれます。`.unnotator/` と、`assets.exclude` に一致するもの（既定では `.DS_Store`・`*.tmp` などの隠しファイル）は対象外です。どの拡張機能も判定できない種類のファイルも「不明」として一覧に出ます。再走査しても、アセットは重複せず、作業状態やアノテーションは変わりません。
- **リンク切れ。** ファイルが削除・移動されると、アセットは「リンク切れ」になりますが、アノテーションは残ります。同じ名前・同じサイズの別のファイルが見つかると、再接続の候補として示されます（自動では結びません）。ファイルが戻れば、リンク切れは自動で解消します。
- **外部フォルダ。** プロジェクトの外のフォルダは、`assets.externalRoots` にルートとして追加できます（相対化できるときは、プロジェクトのフォルダからの相対パスで保存されます）。外付けドライブが外れているなどでルートが使えないときは、その下のアセットは「リンク切れ」になり、戻れば元に戻ります。
- **設定。** 「ユーザー」（アプリの設定フォルダ）と「プロジェクト」（`.unnotator/settings.json`）の 2 段で、プロジェクトの値が優先されます。変更はすぐ書き込まれ、Undo の対象でも、未保存の変更でもありません。知らないキー（入っていない拡張機能のものなど）はそのまま保たれ、壊れた設定ファイルは、黙って上書きされず、別名に退避されてから作り直されます。
- **必要な拡張機能。** プロジェクトが使う拡張機能は、`.unnotator/extensions.json`（`{"version": 1, "extensions": [{"id": "...", "version": "^1.0.0"}]}`）に書けます。開いたときに、足りないものや版が合わないものが分かります。このファイルは、読み取りだけで、書き換えません。

### 拡張機能と `unno://`

- **置き場所。** 導入した拡張機能は、`<アプリのデータ>/unnotator/extensions/<id>/<version>/` に展開されます（ポータブル版は実行ファイルの隣の `data/` の下）。同じ拡張機能の複数の版が並べて入ります。拡張機能の情報は、プロジェクトには保存されません。
- **検査。** 拡張機能は、マニフェストのスキーマで検査され、宣言は `<拡張機能の ID>/<名前>` の名前空間つきになり、依存と API の範囲は、依存先が先になる順に解決されます。動かせないもの（依存の欠落・版の不一致・循環・アプリより新しい API・壊れた参照）は有効にならず、理由が「問題」として一覧に残ります。ほかの拡張機能には影響しません。
- **ファイルの種類。** 拡張機能が宣言した種別（拡張子・MIME）が、アセットの媒体種別を決めます。同じ拡張子を複数の拡張機能が宣言したときは、入れた順に依らず同じ結果になります（種別 ID の小さい方が勝ち、拡張子ごとに上書きもできます）。
- **権限** は「宣言と同意」です。同意は拡張機能・版ごとに覚えられ、権限が変わらない更新では聞き直しません。権限が増えたときは、増えた分だけを聞きます。`network` は、同意するまで拒否され、警告つきで確認されます。
- **開発者モード。** オンにすると、マニフェストのあるフォルダを、そのまま読み込めます。`dist/` の変更は通知されます。同じ ID の導入済みの拡張機能より優先されます。
- **`unno://`。** アプリは、`unno://asset/<id>`・`unno://preview/<id>`・`unno://ext/<拡張機能の ID>/...`・`unno://blob/<名前>` でファイルを読みます。Range に対応し、1 回の応答は 4 MiB までです（続きはブラウザが要求します）。パスは、決められたフォルダの外に出られません（リンク・`..`・エンコードされた形は拒みます）。

### エクスプローラー: ツリー・フィルター・ナビゲーション・プレビュー

- **ツリー。** サイドバーのエクスプローラーに、アセットをフォルダ構造のツリーで表示します。フォルダが先で、名前は自然順（`img2` が `img10` より前。大文字小文字と全角半角は区別しません）です。画面に出ている行だけを描くので、10 万件のプロジェクトでも軽く動きます。各アセットに作業状態（未着手 / 作業中 / 完了 / 要確認）とリンク切れの印が出て、フォルダには配下の完了数が出ます。開いたフォルダは、プロジェクトごとに利用者の設定へ記録します（プロジェクト自身のファイルは書き換えません）。
- **フィルター。** 名前の一部・作業状態・媒体種別・リンク切れで絞り込みます。条件は AND で組み合わせ、ボタン 1 つで全部解除できます。一致を含むフォルダは開いたまま残ります。
- **ナビゲーション。** 前へ / 次へ（PageUp / PageDown）、次の未完了（Ctrl+Shift+N）、完了して次へ（Ctrl+Enter）は、ツリーに見えている順序と絞り込みに従います。移動の単位は、媒体種別が宣言するもの（アセット全体か、文書のページのようなアイテムか）です。リンク切れは飛ばして件数を知らせ、末尾では先頭に戻らずに止まります。完了にする操作は、元に戻す 1 回で戻せます。
- **アイテム。** アイテムを提供する媒体のアセットには、展開の矢印が付きます。アイテムはページ単位で読み込みます。提供元が失敗しても、エラーと再試行のボタンが出るのはそのアセットの行だけです。
- **プレビュー。** 拡張機能のエディターが無いときは、エディター領域に表示専用のプレビューが出ます。画像、UTF-8 のテキスト（先頭 10MB）、PDF（システムの WebView が対応する場合）を表示し、それ以外はファイルの情報と「既定のアプリで開く」を出します。プレビューで開いても、プロジェクトは変わりません。

## 開発

変更を終えたとみなす前に、6 つの確認コマンドをすべて通します。

```bash
pnpm lint && pnpm typecheck && pnpm test && pnpm schema:check
cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace
```

| コマンド | 検査する内容 |
| --- | --- |
| `pnpm lint` | Biome と、依存の向き・依存の版の書き方 |
| `pnpm typecheck` | シェルと契約の TypeScript ファイルの型検査（厳しい設定） |
| `pnpm test` | Vitest |
| `pnpm schema:check` | 契約の検査。DB スキーマが空の DB に適用できること、マニフェストの見本の検証、契約の型の検査、`@unnotator/plugin-api` を固めて利用側から使えること |
| `cargo clippy ...` | Rust の静的解析（警告はエラー） |
| `cargo test --workspace` | Rust のテスト。`src/ipc/bindings.ts` が最新であることの検査を含む |

そのほかのコマンド:

| コマンド | 内容 |
| --- | --- |
| `pnpm tauri build --no-bundle` | アプリのバイナリをビルドする |
| `pnpm measure:startup` | ビルド済みのアプリを 5 回起動し、起動時間の中央値と最大値を出す |
| `pnpm ipc:gen` | Rust のコマンドを変えたあと、`src/ipc/bindings.ts` を生成し直す |

### 契約ファイル

システムの各部分の間の取り決めの正本は、次の 5 つのファイルです。直す必要があるときは、ついでに変えず、提案して決めます。

- `crates/core/migrations/{project,recovery}/*.sql`
- `crates/extensions/schema/unnotator-plugin.schema.json`
- `crates/worker/protocol/protocol.ts`
- `packages/plugin-api/index.d.ts`

### 規約

- Rust: テスト以外で `unwrap()` を使わない。エラーは `thiserror`、ログは `tracing`。
- TypeScript: `any` を使わない。画面の文字列は i18n（日英）を通し、色はテーマの CSS 変数で指定する。
- コミットは [Conventional Commits](https://www.conventionalcommits.org/ja/) に従う。
